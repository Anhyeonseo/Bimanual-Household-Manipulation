# STM32 0x00020A00 후보 거부와 rollback

## 목적

`0x00020900`에서 관찰된 정착 오차를 다루기 위한 heartbeat/settling 후보
`0x00020A00`을 실물에서 제한 검증했다. 이 버전은 최종 배포에서 제외했다.

## 무결성 및 초기 gate

- 후보 HEX SHA-256:
  `075ae168545ac319db91f6acb5fc2ad719892e582edcf8f0e03d74633b752fe6`
- OpenOCD program/verify/reset: PASS
- HELLO: firmware `0x00020A00`, calibration `0xC9EAA589`
- stop latch: `0`
- host identity gate: PASS
- READ_ONLY와 MOTION_ENABLED 무동작 연결: PASS

## 실패

Elbow `0.180 rad / 2 s` 증가 방향 정착 시험에서 firmware는 motion 완료
상태를 보냈지만 최종 오차가 허용 20 raw를 1 raw 초과했다.

```text
ARM_EXECUTION_TERMINAL state=aborted status=6 detail=21
reason=final error 21 exceeds 20 raw; soft abort without safety latch
safety latch error: STM32 stop is latched
```

host의 soft-abort 정책과 달리 STM32 stop latch가 다시 걸렸으므로 후보를
안전하게 계속 사용할 수 없다고 판정했다. 중력에 의한 정착 오차 가능성과
별개로, soft-abort가 latch를 유발한 계약 위반 자체가 거부 사유다.

## 복구

1. bridge 종료, 12 V OFF, 팔 지지
2. 검증된 `0x00020900` HEX로 OpenOCD program/verify/reset
3. rollback HEX SHA-256:
   `569a129802434c1953518acf86c327c592601f44cb214129eca9712c8a324cf6`
4. host identity를 `0x00020900`으로 복구하고 rebuild
5. HELLO firmware `0x00020900`, calibration `0xC9EAA589`,
   stop latch `0`, identity gate PASS 확인
6. 실패 후보 파일명에 `REJECTED_heartbeat_latch` 표기

## 최종 판정

- `0x00020A00`: REJECTED, 배포 금지
- rollback: PASS
- 이후 범위 동기화만 포함한 `0x00020B00 / 0x4D62F8D5`을 별도 검증해 채택
- 생성된 ELF/HEX/BIN/MAP은 재현 가능한 빌드 산출물이므로 Git에서 제거
- 실패 원인, 후보/rollback SHA와 로그 핵심은 이 문서로 영구 보존
