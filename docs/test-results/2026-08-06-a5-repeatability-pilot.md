# A5 — 잔차 재현성 pilot

2026-08-06 · firmware `0x00022A00` · calibration `0xB317C672` · 자동 재시도 0 ·
시리얼 직접 개방 0 · 전체 회귀 **923 통과**

**결론: 정착 후 재현된다. offset 이 남은 잔차를 흡수하는 방식이 성립한다.**

## 무엇을 물었나

C2 가 남긴 유일한 큰 미지수다. 파지는 잔차 `10.17 mm` 와 `7.75 mm` 에서
성립했으므로 과제 허용치 `4 mm` 는 필요조건이 아니었고, 남은 잔차는
`PICK_GRASP_OFFSET_M` 이 흡수한다. **그것이 성립하려면 잔차가 회차 간
재현되어야 한다** — A4 가 실패한 이유도 잔차가 컸기 때문이 아니라 회차마다
달랐기 때문이다.

한 회차: `q0 → pregrasp → grasp → 수렴 → 닫기(관측) → 열기 → q0`

## 워밍업 전이가 있다

1~2회차가 `8.303` / `11.620` 으로 다르고, 3회차부터 `10.5` 로 정착한다.
전체 범위만 보면 `3.317 mm` 라 **재현되지 않는 것처럼 보인다.**

첫 판정 스크립트가 전체 범위만 봐서 "재현되지 않는다" 로 잘못 읽었다.
워밍업과 정상상태를 갈라 보고하도록 고쳤고 시험으로 고정했다.

**시연에서 세션 첫 회차를 쓰면 안 된다.** `3.3 mm` 차이는 A4 스윕의
`3 mm` 간격과 같은 크기이고, 그 간격이 놓침과 파지를 갈랐다.

## 과제 허용치에 대한 최종 판단

**값을 키운 것이 아니라 질문이 바뀌었다.** `4 mm` 는 그대로 두되, 파지
성공의 판정 기준으로 쓰지 않는다.

| | 종전 | 지금 |
|---|---|---|
| 묻는 것 | 잔차가 `4 mm` 안인가 | 잔차가 재현되는가 |
| 근거 | A4 스윕(명령 공간)의 절반 | A5 정착 흩어짐 `0.094 mm` |
| 남은 잔차 처리 | 줄여야 한다 | **offset 이 흡수한다** |

수렴 계층의 값은 잔차를 `0` 으로 만드는 데 있지 않다. **작게 만들고,
측정 가능하게 만들고, 재현되게** 만드는 데 있다.

## 중단 — 첫 프레임이 admission 을 통과하지 못했다 (원인 미확인)

7회차 pregrasp leg 이 host admission 에서 거부됐다.

```
stage=prime_frame_1 precompute_ms=385.777
error=buffered response failed host admission
```

**원인은 아직 모른다.** 첫 설명으로 "precompute 가 startup lead 를
넘겼다" 고 적었으나 **틀렸다** — 코드상 precompute 뒤에
`reanchor_buffered_execution_plan` 이 있어 그 시간은 흡수되고 lead 를 깎지
않는다.

실제 실패 지점은 첫 프레임에 대한 펌웨어 응답이 host 의 admission 검사를
통과하지 못한 것이다(`acknowledge_motion_result`). 그 검사는 status_code,
sample_count, apply_tick_ms, calibration_hash, executor_state,
terminal_reason, safe_stop_required, queue_result 를 본다.

**어느 필드가 어긋났는지는 기록되지 않았다.** adapter 가 상세 메시지를
만들어 던지는데 드라이버가 `"buffered response failed host admission"` 이라는
일반 문구로 덮어썼기 때문이다. 그 결함을 고쳤으므로 다음에는 사유가 남는다.

확실한 것은 **팔이 움직이지 않았고 fail-closed 로 멈췄다**는 것뿐이다.
precompute `385.777 ms` (A4.5 때 같은 leg 이 `186.195 ms`)는 Pi 가 인식
스택과 함께 돌면서 느려졌다는 신호이며, 그 자체가 원인인지는 확인되지
않았다.
