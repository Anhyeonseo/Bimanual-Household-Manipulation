# 현재 진행 상황

기준일: 2026-09-10

**ALOHA Mini 1 기반의 Classical Fetch-and-Deliver를 우선 완성한다.** 대표 작업은 거실 소파의 리모컨을 집어 침대의 지정 영역에 내려놓기다. 이후 리더암 시연 데이터로 VLA를 모방학습하고 동일한 태스크에서 Classical과 비교한다.

## 확보한 기반과 현재 통합 상태

| 구성 | 상태 |
|---|---|
| 기존 Classical P&P | [별도 저장소](https://github.com/Anhyeonseo/Bimanual-Pick-And-Place)에 실기 기반 확보. 카메라 인식→왼팔 집기→오른팔 전달→놓기 완료. 모바일 이식 전 |
| STM32·팔 브릿지 | 펌웨어 179개 파일 보존. `so101_arm_bridge`의 양팔 v2 명령·피드백·관절 한계·정지 경로 유지 |
| 로봇 형상 | 팔 매크로와 mesh 14개 보존. ALOHA Mini 베이스·리프트·양팔 조립체와 센서 TF 미등록 |
| 작업 계획 | `home_robot_tasks`의 요청 검증·7단계 계획 출력 구현. 물리 실행기 없음 |
| 모바일 통합 | 베이스 드라이버, odometry, Nav2, RGB-D, 미세 정렬, 리프트, P&P 연결 미구현 |
| VLA | Classical 완성 후 리더암 시연 수집·학습·비교 예정. 모델·데이터셋 미선정 |

기존 P&P가 없는 상태에서 새로 시작하는 프로젝트가 아니다. 이 저장소의 미구현 항목은 모바일 통합 범위를 뜻한다. 이식할 때 기존 실행 경로와 검증 기록을 확인하고 사용할 코드·의존성·원본 리비전을 기록한다. 고정 작업대의 좌표·보정값·자세를 새 조립체에 그대로 적용하지 않는다.

## 검증 이력과 한계

저장소 기반 재구성 때 Python 시험 173개, 펌웨어 공통 코어 host CTest 9개, ROS 2 Jazzy 패키지 4개 빌드가 통과했다. 설치된 인터페이스·계획 진입점·좌우 팔 모델 참조와 보존 파일 해시도 확인했다. 이는 모바일 주행이나 리프트·집기 통합 성공을 의미하지 않는다.

현재 계획 예제는 `plan_only`, `executable=false`이며, 출발 방의 탐색 후보를 소파로 설정하고 `bedroom_drop_zone`을 침대의 지정 영역으로 사용한다. 미세 정렬·리프트·재인식을 명시적으로 실행하는 상태 머신은 앞으로 추가한다. 모터 동작·보드 플래시·모바일 실물 시험과 원격 CI 실행은 수행하지 않았다.

## 바로 다음 작업

1. ALOHA Mini 1의 실제 바퀴·리프트 제어 경로, 피드백 제공 여부, 통신·정지 동작을 확인한다.
2. 베이스 단독 제어→기구학·odometry→IMU·LiDAR 위치 추정→Nav2 순서로 연결 가능성을 검증한다.
3. 리프트 범위·반복성, 팔 도달 범위와 운반 가능 무게도 초기에 확인해 대표 작업의 높이·접근 공간을 결정한다.

베이스 PoC 통과 후 RGB-D·리프트·기존 P&P를 단계적으로 통합한다. 구체적인 통과 조건은 [로드맵](ROADMAP.md), 모듈 책임은 [시스템 구조](ARCHITECTURE.md), 하드웨어 확인 항목은 [하드웨어 등록](../hardware/README.md)을 따른다.

수건 접기 이력은 [보관본](https://github.com/Anhyeonseo/SO101-Towel-Folding/tree/5b16fff82e400e4cca8cdcff96a6d1548058ef80)에 분리되어 있다.
