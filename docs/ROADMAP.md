# 개발 로드맵

목표는 ALOHA Mini 1으로 **소파의 리모컨을 찾아 침대의 지정 영역에 배달하는 Classical 동작**을 완성하는 것이다. 기존 [P&P 기반](https://github.com/Anhyeonseo/Bimanual-Pick-And-Place)을 재사용하고, 이후 리더암 시연 기반 VLA와 비교한다. 현재 구현 상태는 [현재 상태](CURRENT_STATUS.md)를 따른다.

## Classical 우선 개발

| 단계 | 작업 | 통과 조건 |
|---|---|---|
| M0. 하드웨어 확인 | 바퀴 명령·피드백·정지, 리프트 제어·원점·위치 피드백 조사. 팔 도달·무게·접근 높이 확인 | 실제 프로토콜과 가능한 관측을 확인하고 첫 작업이 기구 범위에 들어옴 |
| M1–M3. ROS 베이스 | 속도 명령, 3륜 옴니 기구학 보정, 바퀴 상태 기반 odometry | 전후·좌우·회전 방향과 단위 일치, 통신 단절 시 정지, 변위 추정 오차 기록 |
| M4–M7. 주행 PoC | IMU 융합, 2D LiDAR, 지도·위치 추정, Nav2 waypoint 이동·반복 정차 | 지정 장소 왕복, 위치 추정·정지 검증, 정차 위치·방향 분산 측정 |
| M8–M10. 작업 조건 재현 | RGB-D 물체·작업면 추정, 베이스 미세 정렬, 리프트 제어·TF·이동 후 재인식 | 보정·관측 시각 유효, 정렬·높이 오차가 기존 P&P의 허용 작업 범위 안에 들어옴 |
| M11–M12. P&P 이식 | 기존 Classical 인식·계획·실행 코드 검토·재사용, 새 물체·장착 조건 적용, 집기 확인·복구 | 정지한 베이스·리프트에서 집기·유지·놓기를 실제로 확인, 실패와 재시도 종료 검증 |
| M13. 전체 배달 | 출발→집기→운반 자세→도착→놓기 상태 머신, 취소·timeout·유한 재시도 | 지정 두 지점의 반복 배달과 물체 분실·접근 불가·통신 실패 처리 확인 |
| M14. 자연어 요청 | 명령을 물체·출발 장소·도착 영역으로 변환 | 동일 Classical 실행기로 연결, 모호하거나 지원하지 않는 요청 처리 |

베이스/Nav2 PoC를 통과하기 전 전체 기능을 한꺼번에 통합하지 않는다. 리프트·팔의 물리 범위는 M0에서 먼저 확인하고 제어 통합은 M8–M10에서 진행한다. 초기에는 정형 요청과 알려진 semantic waypoint를 사용하며 자연어 모델은 필수가 아니다.

반복 횟수·허용 오차·시간 제한은 하드웨어 확인 후 시험 전에 정한다. 위치·높이·하중별 성공 조건을 기록하고 계획 출력과 실물 결과를 구분한다. 소파·침대는 높이뿐 아니라 물체 파묻힘, 표면 변형, 그리퍼 접근 공간도 확인한다. 첫 실물 통합은 접근하기 쉬운 지정 면에서 시작해 대표 환경으로 넓힌다.

## M15. 리더암 시연 기반 VLA 확장·비교

Classical 전체 배달 완성 후 진행한다. Classical을 기준 구현으로 유지하고 조작 모듈을 교체해 비교한다.

1. 리더암 조작으로 영상·언어 지시·팔/그리퍼 상태·행동·시각·성공 결과를 동기화해 기록한다. 수집 및 평가 데이터의 배치를 분리한다.
2. VLA 모델과 학습·추론 장치를 선택하고 시연 데이터로 모방학습한다. 모델 종류와 데이터 규모는 이 단계에서 결정한다.
3. 초기 VLA는 베이스와 리프트를 고정한 상태에서 팔·그리퍼만 제어한다. 주행·미세 정렬·리프트·완료 판정은 공통 계층을 사용한다.
4. 동일 물체·배치·주행 조건·재시도 예산에서 조작 성공률, 전체 배달 성공률, 소요 시간, 재시도·사람 개입 횟수, 새로운 배치에서의 성능을 비교한다. 데이터 수집·학습 비용도 별도로 기록한다.

VLA 단독 평가 중 Classical 복구를 사용하면 해당 시도를 별도로 집계한다. 실제 운영에서 전환할 때는 현재 팔·물체 상태를 확인하고 복구 가능한 시작 조건을 만든다. 베이스·리프트·팔 전체를 학습 정책이 동시에 제어하는 방식은 현재 범위에 포함하지 않는다.

## 이후 확장과 남은 선택

추가 강체·물건 정리·빨래 수거는 첫 배달과 비교 평가 이후 확장한다. 센서 제품·장착 위치, 컴퓨팅·전원 배치, 리더암 구성·VLA 모델은 미정이다. 대표 운반은 물체를 잡은 채 운반 자세를 유지하며, 구체적인 자세·주행 속도·가능 무게는 실물로 검증한다. 제품 이름만으로 치수·TF·payload·feedback API를 확정하지 않는다.
